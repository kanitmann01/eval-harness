annotations 01-12

  1. 01
    header

    Counts on the left, one primary action on the right. The primary action is New comparison, the same one the Runs page carries, so the wizard is reachable from both places.

  2. 02
    label and route

    The nav says Comparisons, the route stays /specs. The rename is a label change only, and the file name is still the name used by the CLI, so a script does not break.

  3. 03
    table

    One row per YAML file. The file name is the identity, the display name comes from inside the file, and both are shown.

  4. 04
    what varies

    The axes summary is the cheapest answer to what this comparison changes, 3 prompts x 1 model, with candidate and case counts under it.

  5. 05
    estimate

    Price table times observed medians for the cells this spec would run. It is an estimate, the run page holds the recorded cost.

  6. 06
    last run

    Run id plus the verdict of that run. A valid spec can have a failing run, and the row says which happened.

  7. 07
    actions

    Run is primary here because a saved comparison exists to be run. Edit opens the structured form, Duplicate copies the YAML, YAML opens the raw file.

  8. 08
    invalid spec

    The row shows the field, the bad value and the fix. Run is disabled and names the reason on the button, Edit stays open so the file can be fixed.

  9. 09
    never run

    A valid file with no runs shows never run and keeps Run enabled. No verdict is invented for it.

  10. 10
    gate verdict

    A run that finished ok and failed its gate shows ok plus a gate chip, never a single merged status.

  11. 11
    duplicate

    Copies the file to name-copy.yaml, opens it in the YAML editor, and leaves the original untouched. Nothing is saved until the copy is written.

  12. 12
    mobile

    One card per comparison: name, axes, estimate, last run, then actions in a row of 44px targets.
