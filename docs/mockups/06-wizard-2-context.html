annotations 01-12

  1. 01
    step rail

    Second step marked current, first step still clickable so a name change is one click away. The estimate stays put: contexts do not change it until one is attached.

  2. 02
    context sets

    One row per named set with the chunk count and total characters measured now. A cell that reads 5 chunks at 690 characters is a cost the operator can see.

  3. 03
    sources

    Paste text, upload a file, or import a knowledge graph export. The exported graph arrives as one named set, not as loose nodes.

  4. 04
    attach here or in step 3

    Attaching to all candidates here is the shortcut. Step 3 keeps a per candidate selector, which wins over this default.

  5. 05
    credentials block

    Lists the adapter each model needs, the credential in the vault, its fingerprint prefix and its last test. It does not ask for a key on this page.

  6. 06
    untested credential

    Untested is not the same as broken. It blocks selection on step 3 and points at the credentials page, it does not stop the draft from being saved.

  7. 07
    chunking

    Chunk count and characters are produced by the same chunker and settings the run will use, at 200 characters with 40 overlap. No estimate from a different tokenizer.

  8. 08
    multiplication

    Contexts are an axis too. One set attached to all candidates leaves the count alone, two sets attached to all candidates double it.

  9. 09
    nothing written

    The footer repeats that the draft is still in the form. Leaving here keeps the draft, nothing is created on disk.

  10. 10
    footer

    Back and Next. Back does not lose edits, the draft YAML travels in the hidden field either way.

  11. 11
    upload errors

    An unreadable upload names the file, the line and the fix, and the set is not attached. Partial attachment is never silent.

  12. 12
    mobile

    The rail becomes a horizontal strip, the context table becomes one card per set with the counts on the second line.
