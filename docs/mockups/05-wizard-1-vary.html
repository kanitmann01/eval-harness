annotations 01-12

  1. 01
    step rail

    Four steps, current one filled, completed ones still clickable. The estimate sits at the bottom of the rail and moves with every edit, so the cost is visible before step 4 asks.

  2. 02
    step title

    One line states what the step decides. The wizard writes nothing until step 4, so the header says draft not written yet instead of pretending a file exists.

  3. 03
    name and slug

    Free text name, with the file it will write shown underneath. The slug is what the CLI and the route use, so a rename is visible before it happens.

  4. 04
    test cases

    Pick from cases already saved in a spec, paste YAML or JSON, or upload. The four support-routing cases arrive ticked because this comparison extends that spec.

  5. 05
    prompt axis

    Named variants, one textarea each. The name is free text and lands in the candidate name, so the table on step 3 reads mini-concise not prompt-1.

  6. 06
    model axis

    One row per model with temperature and max_tokens on the row. Parameters are per model because a temperature that suits one provider does not suit another.

  7. 07
    replicas and concurrency

    Replicas multiply cells, concurrency does not. Concurrency is a runner setting, and it is capped by the number of cells.

  8. 08
    no varying axis

    Next is disabled when no axis varies, with the reason next to the button. One candidate and one case is a test, not a comparison.

  9. 09
    cell count

    The product of prompts, models, cases and replicas, restated in words. It updates as fields change and it is the number step 4 multiplies by cost.

  10. 10
    estimate in rail

    Provisional until step 4 confirms the price table and the medians source. The rail value and the step 4 hero must agree, one number, two places.

  11. 11
    footer

    Back and Next only. Next posts the draft YAML in a hidden field, so a refresh or a deep link rebuilds the same step from the spec.

  12. 12
    mobile

    The rail becomes a horizontal step strip above the body, the fields stack full width, and the estimate moves under the strip.
