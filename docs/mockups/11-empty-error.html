annotations 01-12

  1. 01
    two states

    Both live in one file so the copy and the buttons can be compared. Error on the left, empty list on the right, same shell, same nav.

  2. 02
    error page

    One page for unknown runs, unknown specs, path traversal and missing artifacts. That is why the copy names the request instead of hard coding run.

  3. 03
    what was asked

    The id is shown back exactly as it arrived, in mono, so a user can see a truncation. The failing path is stated in the line below, not buried in a quote.

  4. 04
    way back

    Primary goes to the nearest list, secondary to compare, which is where a person usually was. Both are links, so they work with middle click.

  5. 05
    no internals

    No stack trace, no traceback id, no filesystem path. The response is a normal HTML page with the console shell, not a debug dump.

  6. 06
    status label

    Not found is a text label, not a colour. The page says what the server answered, in words, with no icon standing in for the reason.

  7. 07
    empty list

    The empty state sits where the table would be. Title, one sentence of what a run is, one primary action, one secondary link.

  8. 08
    empty vs filtered

    The note under the header row separates the two. Filters on with no match stays on the list page and says no runs match these filters, with a Clear.

  9. 09
    call to action

    create your first comparison goes to step 1 of the wizard, not to a run. Naming the comparison rather than the run matches the product's unit of work.

  10. 10
    cost before spend

    The empty state carries the estimate, so the first click is informed. The number is the same one the wizard rail shows at step 4.

  11. 11
    mobile

    The error page keeps the way back inside the first 375 by 500. The empty state keeps the call to action above the fake table header.

  12. 12
    shell

    Both states keep the nav and the console strip. A user who lands here is not trapped, and the page does not pretend the console is gone.
