annotations 01-12

  1. 01
    header

    Counts first: stored, usable, needs attention. A user arriving here is usually fixing the third number, so it is on the same line as the title.

  2. 02
    add form

    Three fields, no optional ones. Name is unique, provider picks the adapter, secret is written once. Store is disabled until name and secret are non-empty.

  3. 03
    table

    One row per stored credential, newest first. This is the only place a credential is edited, the wizard only selects from here.

  4. 04
    fingerprint

    Prefix only, followed by an ellipsis. Reveal shows four more characters for one row, and the full key is never returned by the API.

  5. 05
    state

    Four states, each with a one line meaning at the bottom of the page. A read only badge would leave the user guessing why a credential is not in a dropdown.

  6. 06
    actions

    Test runs a real call and reports models listed and latency. Disable is reversible and keeps run records. Delete asks for the name to be typed, then removes the row.

  7. 07
    test result

    The result lands inline under the table and replaces the last result for that row. No toast, no modal, the row stays visible.

  8. 08
    last error

    Provider message with the key redacted by the adapter. 401 invalid_api_key is enough to act on and reveals nothing.

  9. 09
    untested

    Unverified is not an error here, it is a state the wizard enforces. The link goes to the exact step that blocks on it.

  10. 10
    vault locked

    When locked, the table renders names and states but the fingerprint and actions are disabled, with the reason in a callout, and nothing 500s.

  11. 11
    empty

    No rows means a short line, the add form open, and one sentence naming what a credential is for. Same page, not a separate empty route.

  12. 12
    mobile

    One card per credential: name, provider, state, fingerprint, then two buttons at 44px. The provider and state stay on the first line.
